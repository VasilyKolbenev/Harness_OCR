# Готовность Харнесс OCR к передаче

Версия 0.1.0rc2 подготовлена для инженерной приёмки на Linux и RTX. Полнота программных модулей, сборка контейнера, реальный GPU-инференс и качество документов — разные требования. Передача исходников не означает разрешения промышленного автозаполнения.

## Соответствие компонентов

| Компонент | Связь с движком | Проверка | Граница |
|---|---|---|---|
| F01 состояние | Реальные наблюдения, выбор Qwen, конфликты и правки входят в DocumentStore | Атомарность, зависимости, отзыв источника, конфликт, CAS человека | Новый источник не восстанавливает старый вывод без нового доказательства |
| F02 trace/replay | Каждая стадия пишет трассу; offline-адаптер читает проверенную цепочку | Цепочка SHA, повтор кандидатов/resolve без нейросети | Внутренний механизм нейросети не объясняется трассой |
| F03 профили | Engine, HTTP, MCP и research используют одну декларацию | Фактический результат проверяется JSONSchema; неизвестные условия не становятся false | 10 деклараций не равны 10 квалифицированным макетам |
| F04 слепой экзамен | Адаптер замороженной трассы вызывает настоящий Qwen text-verifier через Supervisor | Приватные метки не попадают в prompt; строгий verdict и учёт наблюдаемости | Визуальный verifier пока не подключён к штатному backend |
| F05 минимизатор | Пересобирает кандидатов и resolver из сохранённой трассы | Тот же task, evidence и класс дефекта; новые NN-вызовы не нужны | Это диагностический reducer, не поиск нейронной причины |
| F06 аудит/дрейф | Публикация результата, случайный отбор, авторизованный outcome и карантин | Вероятность отбора, защищённые события и отзыв автоматизации | Разные фото одного физического документа не объединяются автоматически |
| F07 стратегии | Утверждённые scoped-карточки входят в Qwen prompt и серверные ограничения | Версии, активация/отзыв, хеши и negative findings | Неисполняемые директивы вызывают review |
| F08 риск | Только доверенная конфигурация и активная policy точного binding | Раздельные calibration/qualification/test, обязательные поля и evidence | Production-политики и показатели риска для реального потока ещё не квалифицированы |
| F09 oracle | DEV-адаптер настоящей selector-стадии с факторами текст/роли | Gold остаётся у scorer; маркировка вмешательства; полный 2×2 | Не вызывается из production API; не доказывает мировой новизны |

Проверки исполнения и упаковки: [deployment-readiness.md](deployment-readiness.md). Полный список runtime-дефектов и регрессионных сценариев: [runtime-audit.json](runtime-audit.json). Форматные валидаторы и их источники: [validator-sources.json](validator-sources.json).

## Что изменено после первого RC

Первый RC имел рабочие базовые сценарии и 150 тестов, но аудит обнаружил неполные связи между модулями. Исправлены продолжение очереди при неуспешной проверке весов, скрытый сбой scheduler, гонки отмены, блокировка устройства между API/benchmark и осиротевшими воркерами, неполная готовность Docker healthcheck, потеря незавершённых перечитываний и устаревшие конфликты источников.

Добавлены связи меток со значением справа/ниже в ограниченном графе, буквальная сборка ФИО из явно размеченных компонентов, видимость исходного графа и стратегий для Qwen, расширенные валидаторы и версионированная серверная применимость. Подтверждённые противоречащие чтения доходят до F01 независимо от выбора модели.

Новый тестовый набор включает эти регрессии. Актуальный результат запуска хранится в GitHub Actions для конкретного коммита. Ни число тестов, ни один синтетический CPU-пример не оценивают прикладную точность OCR.

## Поля с незавершённым типизированным контрактом

Эти поля явно возвращают `not_checked` до подключения проверенного контракта версии. Их наличие блокирует квалификацию полного профиля; минимальный subset рассматривается отдельно.

| Профиль | Поля |
|---|---|
| D04 доверенность | `principal.identifier`, `representative.identifier` |
| D05 паспорт самоходной машины | `machine.main_identifier`, `ownership.entries` |
| D06 регистрация техники | `machine.main_identifier` |
| D07 платёжное извещение | `payee.accounts` с разделением типов счетов |
| D10 ОМС | `policy.number` с привязкой к версии полиса |

Проверка формата обычного поля также ограничена своим `validation_scope`: она не подтверждает оптическую правильность, принадлежность счёта, подлинность документа или результат услуги. Исторические и неразрешённые версии сохраняют `not_checked`.

## Native источники

Общее XML-декодирование сохраняет структурные наблюдения, но не имеет права наследовать квалификацию raster-профиля. Без зарегистрированного адаптера конкретной схемы извлечение завершается явным отказом с сохранением диагностики. Адаптер реальной МЧД, проверка подписи и подключение доверенных реестров остаются отдельной интеграцией.

## Условия допуска к промышленному потоку

1. Чистая Linux-установка, тесты и настоящая сборка Dockerfile прошли на передаваемом коммите. Ссылка на CI показывает фактическое состояние, а не заявленное наличие YAML.
2. На целевой RTX выполнены doctor, API/review/cancel acceptance и A0/A1/A3/A4. Зафиксированы версии, SHA, остановки, VRAM и задержки; CPU FP32 не заменяет GPU BF16.
3. Для каждого поддерживаемого макета и контракта размечены независимые реальные документы. Ошибки значений, ролей и отказы считаются отдельно; связанные фото не считаются независимыми оригиналами.
4. Закрыты необходимые поля и адаптеры выбранных услуг. Политика F08 квалифицирована на отдельной выборке и активирована сервером для точного binding.

До выполнения этих условий автоматическое принятие закрыто. Движок можно использовать для инженерной приёмки и контролируемой ручной проверки; уверенное покрытие 30–50 типов документов пока не установлено.
