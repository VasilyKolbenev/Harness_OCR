Adaptive GPU comparison (separate from the immutable legacy benchmark)

Metadata preflight, before downloading weights; CUDA and models are not imported:
  python -m experiments.gpu_delivery.run --manifest /input/own-documents.json --models /models --lock-dir /locks --output /reports/plan

Real target-GPU matrix, after model verification/doctor/smoke:
  python -m experiments.gpu_delivery.run --manifest /input/own-documents.json --models /models --lock-dir /locks --output /reports/comparison --qwen both --total-seconds 10800 --execute

--qwen both is the four-arm default: Qwen0.8B and4B, each with adaptive DB versus DB+YOLO-L rescue. --qwen qwen-0.8b or qwen-4b narrows the selected models; --include-yolo-x explicitly adds DB+YOLO-X for each selected Qwen. Rescue is lazy: a configured detector may never be called if no unresolved field needs it. The safe summary records actual action counts and rescue_activated, not an assumed detector contribution.

Input is exactly harness-own-documents/1 as documented for scripts/run_documents.py: {schema_version,documents:[{id,path,profile_id,subset?}]}. Paths are relative to the manifest directory and cannot escape it; profile/subset IDs are validated. Images, PDFs and supported native XML are accepted without guessing their type/profile. Inline gold/unknown keys are rejected. An explicit synthetic helper can produce a manifest when no operator documents exist; this runner never guesses profile labels from filenames or values.

Default common settings: CUDA BF16 SDPA,4 CPU threads,input32768/output1024,call300s/document900s,2 targeted reads,1 detector rescue,1 whole-page fallback,2 blind visual regions. Limits have explicit CLI flags and are the same across arms. No attention/dtype/CPU fallback, dynamic threshold tuning, normalized gold, forced Cyrillic, best-of selection or automatic winning model.

Each document/arm is a fresh Python interpreter, Engine state and single Supervisor. No final optics, candidate claims or model state cross arm boundaries. A fail-stop facade forbids worker restart after the first backend exception. The matrix coordinator holds gpu-delivery.lock; every real owner holds the existing CUDA admission+compute leases. All callers must mount the same lock volume. Another live owner is not killed. Fresh rows run sequentially; errors are not retried. A fatal integrity/cleanup/warmup failure stops the sweep, leaving every unobserved pair explicit.

Warmup/load, document execution, fresh-row wall and preflight are separate. Existing ResourceSampler samples matching runner/worker RSS and attributable NVML GPU memory, while model calls retain PyTorch allocated/reserved peaks. These are different quantities. Null is unmeasured, never zero; resource_measurement_complete is separate from technical_execution_passed. Successful Engine action_counts are distinguished from backend_action_attempts (including failed requests); later requests refused by the fail-stop facade are counted without pretending they executed. GPU throughput/capacity and production quality are not qualified by this one sequential run.

The total deadline starts before setup/manifest/hash verification and includes load/close/final verification. An optional --absolute-end-utc can shorten it.15s cleanup and30s final-hash reserve are withheld from model time. The worker sees global cancellation; a PID+creation-time watchdog closes only verified descendants after the original deadline. Ctrl-C stops without automatic restart. Model bytes are SHA-verified before and after, stat-guarded each row; code and source documents are rechecked. If integrity cannot finish within the same total budget, it is incomplete rather than silently extending the run.

Optional exact gold is a separate file supplied via --gold. The coordinator validates schema/profile field IDs before weight preparation/NN (also in metadata-only plan), records its SHA and discards reference values. Fresh worker specifications have a closed whitelist containing no gold. The coordinator opens gold again for scoring only after every model owner exits:
  {"schema_version":"harness-gpu-delivery-gold/1","documents":{"operator-id":{"payer.name":"literal exactly as annotated"}}}
Only declared document IDs and requested field keys are legal, with at least one annotated document/field. V1 references must be nonempty exact raw STRINGS (at most8192codepoints); dictionaries, lists, typed-semantic identities, empty strings and duplicate JSON keys are explicit preflight errors. References to structured typed fields are rejected even when supplied as strings: those require a separate explicit typed-semantic protocol. Typed/native structures still run technically, but this scalar-reference format does not measure their semantic correctness; scalar native names/dates can use ordinary string references. There is no normalization, checksum repair or value_identity projection. Missing results remain unmeasured; review, partial recovery, completion and exact correctness are distinct. A format-valid literal is not proof of correct recognition, and review is not a technical execution failure. Without gold the summary says correctness_unmeasured=true, with no invented0% accuracy or quality pass.

PRIVACY / return bundle contract

summary.json and quality.json are LOCAL report inputs, not the shareable bundle. Their main fields contain opaque IDs, counts, hashes and resources, but nested diagnostics must not be treated as a general privacy guarantee. Share only RETURN_TO_TEAM.zip generated by scripts/export_gpu_delivery.py: its strict allowlists retain numeric/boolean fields and counts of diagnostic errors, never arbitrary error text, paths, raw values, prompts, environment or logs. The ZIP includes sanitized HTML/CSV/summary-public.json and hashes. Do not send summary.json or other local artifacts instead of the ZIP.

Native ingestion is explicit via native_ingestion_present; model_generation_calls and zero_generation_document distinguish it from OCR/selector/visual generation. A successful MCHD ingestion plus CUDA warmup is not evidence of GPU document-generation execution. CUDA warmup, NVML process memory and PyTorch generation peaks are reported separately.

Everything else is protected by default. protocol.json/plan.json retain private local paths and IDs; rows contain raw result/optics/state, prompts in traces, images and logs. Do not zip the whole output tree for ordinary sharing. Full raw artifacts require a separate explicit operator decision. No files or reports are uploaded by this runner.

Exit0 means all planned rows completed technically with owner cleanup and verified source/model integrity. Exit1 means failed/incomplete technical execution; exit2 means operator stop/administrative budget. Review and exact accuracy never cause a technical failure by themselves. Raw values are never replaced to improve the report.
